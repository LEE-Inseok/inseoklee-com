개념 정리

▾

Claude Code 생태계를 구성하는 8가지 핵심 개념. 위에서 아래로 추상화 수준이 높아진다.

🔧 Tool Layer 1
Claude가 직접 쓰는 내장 도구 하나. 파일 읽기, 코드 수정, 검색, 쉘 실행 등 가장 작은 실행 단위.
🏗️ 망치, 드라이버, 펜치 같은 개별 공구
Read Edit Write Bash Grep Glob
🔌 MCP Tool Layer 1+
외부 서비스와 연결하는 도구. MCP 서버가 중간 다리 역할을 해서 Notion, Gmail 등을 Claude가 직접 조작할 수 있게 함.
🔌 USB 허브에 외장장치를 꽂는 것
Notion Gmail Chrome Claude Preview
↔ Tool과의 차이: Tool은 내장, MCP Tool은 외부 서버 경유
📡 API Layer 1+
외부 AI 모델을 직접 호출. Codex CLI를 통해 GPT-5.4/5.3에게 교차 검증 수행. Proxima MCP는 보조용.
📞 다른 전문가에게 전화해서 의견 묻기
ask_chatgpt ask_gemini ask_all_ais
↔ MCP Tool과의 차이: MCP Tool은 서비스 조작, API는 AI 모델 호출
📖 Skill Layer 2
/명령어로 실행하는 재사용 프롬프트 템플릿. 여러 Tool을 조합해 특정 작업을 수행하는 레시피.
📖 요리 레시피 — 도구들의 조합법이 적혀 있음
/commit /recap /pdf /dashboard
↑ Tool을 조합: Skill = Tool + Tool + ... 의 실행 순서
📦 Plugin Layer 3
스킬 번들 팩. 하나의 플러그인이 관련된 여러 스킬을 묶어서 제공. 마켓플레이스에서 설치.
📦 앱 스토어에서 받는 앱 번들 (설치하면 여러 기능이 한번에)
design → 7개 스킬 · anthropic-skills → 6개 스킬
↑ Skill을 묶음: Plugin = Skill + Skill + ... 를 하나의 패키지로
👤 Agent Layer 4
특정 역할의 독립 실행 주체. 자체 도구 세트와 모델을 가지고 자율적으로 판단하며 작업 수행.
👤 팀원 — 각자 전문 분야와 도구를 가진 독립 인격
developer debugger researcher tester
↑ Tool+Skill을 자율 사용: 스스로 판단해서 어떤 도구를 쓸지 결정
🪝 Hook 자동화
특정 이벤트가 발생할 때 자동 실행되는 쉘 명령. Tool 호출 전후, 파일 저장 시 등에 트리거.
🚪 자동 센서 — 문이 열리면 불이 켜지듯, 이벤트가 오면 자동 반응
pre-commit lint · post-edit format · pre-push test
↔ Skill과의 차이: Skill은 사용자가 호출, Hook은 이벤트가 자동 트리거
📋 CLAUDE.md 설정
매 대화 시작 시 자동으로 읽히는 지시 파일. 글로벌(~/.claude/)과 프로젝트별(.claude/) 두 레벨 존재.
📋 직원 매뉴얼/사규 — 출근하면 자동으로 숙지하는 규칙
에이전트 규칙 · 교차 검증 절차 · 응답 스타일
↔ Hook과의 차이: CLAUDE.md는 정적 지시, Hook은 동적 스크립트 실행

Claude Code가 실행될 때 실제로 일어나는 일. 세션 시작부터 결과 출력까지의 전체 흐름.

세션 시작 (초기화)
1 CLAUDE.md 읽기 — 글로벌(~/.claude/) → 프로젝트(.claude/) 순서 설정
2 Memory 파일 로드 — MEMORY.md 인덱스 + 관련 메모리 참조 설정
3 settings.json 적용 — 허용된 도구, Bash 명령어, MCP 서버 목록 설정
사용자 메시지 수신 (실행)
4 Orchestrator(Claude)가 작업 분석 — 무엇을 해야 하는지 판단
5 Tool / MCP Tool 직접 사용 — 파일 읽기, Notion 조회 등 도구
6 또는 Skill 호출 — /commit, /pdf 등 프롬프트 템플릿 실행 스킬
7 또는 Agent 위임 — developer, debugger 등 서브에이전트에게 작업 분배 에이전트
8 필요 시 Codex CLI 교차 검증 — /codex:rescue로 GPT-5.4에게 검증 요청 Codex
작업 완료 (마무리)
9 Hook 트리거 — 설정된 경우 자동 실행 (lint, format, test 등) 훅
10 결과 출력 — 사용자에게 결과 전달, Memory 업데이트 (필요 시)

CLAUDE.md 핵심 규칙 (Global — ~/.claude/CLAUDE.md)
1
서브에이전트 적극 활용
독립 작업 2개+ → 병렬 실행. 10개 에이전트 색상 체계. 전문 영역은 항상 해당 에이전트 사용. 백그라운드 병렬 실행 시 반드시 사용자에게 명시하고 agent별 담당 작업을 표로 안내 (병렬 실행 안내 규칙).
2
GPT 피드백 루프 (Codex CLI — codex-plugin-cc)
Codex CLI를 통해 GPT 교차 검증 수행. 모델 라우팅: code-verifier → /codex:review --model gpt-5.3-codex, plan-verifier → /codex:rescue --model gpt-5.4. 기본 1라운드, critical issue 시 최대 3라운드. 응답: accept / accept with notes / revise. 호출 실패 시 사용자에게 알리고 대기 (자동 fallback 금지).
3
교차 검증 문서 규칙 & 실시간 상태 표시
Claude가 모든 파일 I/O 전담 (Codex sandbox는 로컬 파일 읽기 불가). 요청/응답 파일 작성 후 내용을 프롬프트 인라인으로 전달. 템플릿 양식 필수. 저장 위치: reports/<project>/<work>/YYYY-MM-DD_<session>/. GPT 응답 전 재질문 절대 금지. 각 단계(요청·처리중·수신)마다 상태 메시지 실시간 출력 필수.
4
응답 스타일
진행상황 보고는 progress-tracker를 통해 출력. 불필요한 요약 반복 금지. 작업 완료 후 다음 단계 항상 제시.
글로벌 CLAUDE.md + 프로젝트별 CLAUDE.md 2개 별도 운영
